# AutoRigForHumanoid For Maya

ヒューマノイドのスキンジョイントから、FK/IK切り替え付きのコントローラーリグを自動生成する Maya 用ツールです。
リグ生成に加えて、ポーズ操作用のピッカー、コントローラー形状の引き継ぎ、別ファイルからのリグ読み込み、
ブレンドシェイプ用コントローラーの作成、Unity 向け FBX の書き出しをひとつのウィンドウにまとめています。

## 主な機能

| 機能 | 概要 |
|---|---|
| リグ自動生成 | 関節を割り当ててガイドを作り、位置・向きを確認してからリグを生成。体幹・頭・腕・脚・指に対応 |
| FK/IK 切り替え | 腕・脚の FK/IK をブレンド。ピッカーから IK→FK / FK→IK のポーズ合わせ切り替えが可能 |
| Picker | コントローラーの選択、表示切り替え、ポーズのリセット、左右ミラーを行う専用ウィンドウ |
| コントロールシェイプの引き継ぎ | コントローラー形状(CV座標)を json に保存し、リグ作り直し後に復元 |
| 別ファイルのリグ読み込み | 別の Maya ファイルのリグを、Picker が使える状態(UUID 維持)でシーンへ読み込み |
| ブレンドシェイプコントローラー | ブレンドシェイプを操作する 1×1 / 2×1 / 1×2 / 2×2 のスライダー式コントローラーを作成 |
| FBX 入出力 | FBX のインポート、Unity 向け検証付き書き出し、FBX 内のブレンドシェイプ名の変換 |

## 動作環境

- Autodesk Maya 2025 以降(Picker が PySide6 を使用します)
- Windows で開発・確認しています。他の OS は未確認です
- Unity FBX 書き出しのワーカーは Maya に付属の `mayapy` を別プロセスで起動します

## インストールと起動

1. このリポジトリを Maya のスクリプトフォルダ直下に `AutoRigForHumanoid` という名前で配置します。

   ```
   C:\Users\<ユーザー名>\Documents\maya\scripts\AutoRigForHumanoid\
   ```

   ```bash
   cd "C:\Users\<ユーザー名>\Documents\maya\scripts"
   git clone https://github.com/Gomanosuke/AutoRigForHumanoid.git
   ```

2. Maya のスクリプトエディター(Python タブ)で次を実行します。

   ```python
   from AutoRigForHumanoid import show_window
   show_window()
   ```

   `show_window()` は実行のたびにモジュールを再読み込みするため、コードを編集した後も Maya を再起動せずに反映できます。
   シェルフのボタンにしたい場合は、上のコードをシェルフへドラッグして登録し、`ARFH_icon.png` をアイコンに指定してください。

## 基本の使い方(リグ作成〜ポーズ付け)

前提: スキン済み(または少なくともジョイント階層が整った)ヒューマノイドキャラクターがシーンにあること。

1. **キャラクター名を決める** — `リグ制作` タブの「初期設定」でキャラクター名を入力します(リグ、ガイド、Picker 用データの名前に使われます)。
2. **関節を割り当てる** — Hips / Spine / Chest / 腕 / 脚 / 頭 / 目 / 指 などの入力欄に、対応するジョイントを入れます。
   - `自動割り当て`: シーン内のジョイント名から自動で推測して入力します(名前の規則は [`joint_name.json`](joint_name.json))。
     複数候補があるときは座標の左右・階層の浅さ・名前の短さで絞り込みます。「フルパス」で入力する名前の形式を選べます。
   - `割り当て`: ビューポート/アウトライナーで選択したジョイントを、その行へ入力します。
   - `選択`: 入力欄のジョイントをシーンで選択します(確認用)。
   - 指(Left Hand / Right Hand)は既定で折りたたまれています。指が無いモデルでは空のままで構いません。
3. **ガイドを作る** — 「リグ制作」の `主軸`(ジョイントのアライン軸 X/Y/Z)を選び、`ガイド作成` を押します。
   ジョイントの向きを決める Orient ガイドと、位置を決める Position ガイドが作られます。
   ガイドを動かして手足や体幹の向き・位置を調整します。ガイドの向きは `90°回転` の X/Y/Z ボタンで補正できます。
4. **リグを作る** — `リグ作成` を押すと `<キャラクター名>_Rig` 以下にコントローラー一式が生成されます。
   処理は 1 回の Undo にまとめられ、途中で失敗した場合は自動で元に戻します。
5. **ポーズを付ける** — 常設の `Picker表示` ボタンから Picker を開き、ボタンでコントローラーを選択して操作します。
6. **リグ作り直しが必要になったとき** — `コントロールシェイプ` で形状を書き出しておけば、作り直した後に同じ形状を読み込めます。

## ウィンドウの構成

ウィンドウ上部に **Picker** ボタンが常設され、その下が用途別のタブになっています。

```
AutoRigForHumanoid
├─ Picker              [Picker表示]                  (常設)
└─ タブ
   ├─ リグ制作
   │    ├─ 初期設定            キャラクター名 / 関節の割り当て / 自動割り当て
   │    ├─ リグ制作            主軸 / ガイド作成 / 90°回転 / リグ作成
   │    └─ コントロールシェイプ  Export Shape / Import Shape(既定で折りたたみ)
   ├─ アクセサリ
   │    ├─ リグ読み込み         別ファイルのリグを読み込む
   │    └─ FBX
   │         ├─ FBXインポート          Import FBX / Freeze Scale
   │         ├─ Unity FBX 書き出し     FBX Exporter For Unity
   │         └─ FBX名の整形            ブレンドシェイプ名の変換
   └─ ブレンドシェイプ
        └─ ブレンドシェイプコントローラー  1*1 / 2*1 / 1*2 / 2*2
```

色はタブごとの目印です(Picker=琥珀、リグ制作=青、アクセサリ=グレー、FBX 入力=青緑、FBX 出力=緑、ブレンドシェイプ=紫)。

## 機能の詳細

### 初期設定と自動割り当て(`auto_apply.py`, `joint_name.json`)

`joint_name.json` のキーワードとジョイント名(大文字小文字を区別しない部分一致)を照合して入力欄を埋めます。
`Shoulder`, `UpperArm` / `upper_arm`, `Hand`, `UpperLeg` / `upper_leg`, `Toes` / `toe`, 指の `Proximal` / `Intermediate` / `Distal` などが対象です。
モデルの命名規則が異なる場合は、`joint_name.json` へキーワードを追加してください。

### リグ制作(`autorig_preparation.py`, `autorig_createBase.py`, `autorig_createRig.py`)

- `ガイド作成` は、割り当てたジョイントから Orient / Position ガイドを作ります。キャラクター名が空(または `|` を含む)、入力したジョイントがシーンに無い・複数一致する場合は警告して中止します。
- `リグ作成` は次を行います。
  - 同名の `<キャラクター名>_Rig` が既にある場合はエラーにします(上書きしません)。
  - Orient / Position ガイドが 1 セットに定まらない場合はエラーにします。
  - 生成に失敗したときは Undo で元へ戻します。
- 元のスキンジョイントにリグを接続する方式のため、スキンウェイトの再設定は不要です。リグ作成の失敗時は、元のジョイントへの変更も Undo で戻します。

### Picker(`picker.py`, `designer_ui.ui`)

Qt Designer で作ったピッカー画面です。ホイールでズームできます。

| ボタン | 動作 |
|---|---|
| キャラクター図上のボタン | 対応するコントローラーを選択(Shift 押下で追加選択) |
| All Finger | 指のコントローラーをまとめて選択(指が無いリグでは警告してスキップ) |
| Select ALL | すべてのコントローラーを選択 |
| Reset Pose | 全コントローラーを初期値と単位行列へ戻す(1 回の Undo で戻せる) |
| Mirror Pose | 現在のポーズを左右反転(左右のコントローラーの値を入れ替え) |
| IK>>FK / FK>>IK | 腕・脚の IK/FK を、見た目のポーズを保ったまま切り替え(左右それぞれ) |
| ArmVis / LegVis / HandVis / HeadVis / BodyVis など | 部位ごとのコントローラー表示切り替え(左右個別も可) |
| Flat Shade | すべてのビューポートをテクスチャ表示・フラットライトへ切り替え |

Picker はコントローラーの参照を **UUID** で管理しています。リグの情報は `ARFH_information` ノードの JSON に保存されます。
同一シーンに複数キャラクターがいる場合は、`ARFH_information.characterName` を書き換えることで Picker の対象を切り替えられます。

### コントロールシェイプ(`control_shape.py`)

コントローラーのカーブ形状(CV のローカル座標)を json へ書き出し/読み込みします。

- `Export Shape`: 対象コントローラーの形状を書き出します。
- `Import Shape`: 名前が一致するコントローラーへ CV 座標を書き戻します。CV の数が違うものは崩れるためスキップします。
- 対象は「選択中のコントローラー、またはリグのトップグループなどの子孫の `Con_*`」です。何も選択していなければシーン内の全 `Con_*` が対象です。
  選択の中にコントローラーが無い場合は警告して全 `Con_*` へフォールバックします。

### 別ファイルのリグ読み込み(`rig_import.py`)

別の Maya ファイル(`.ma` / `.mb`)で作ったリグを、Picker が使える状態でシーンへ取り込みます。
Maya の通常のインポートはノードの UUID を再割り当てするため、そのままでは Picker が対象を見つけられません。
この機能は、リグ作成時に `ARFH_information` へ記録した UUID とノード名の対応を使い、インポート直後に元の UUID へ復元します。

- 既にシーンに `ARFH_information` がある場合、読み込んだ側の情報を既存のものへ統合し、重複ノードを削除します。
- UUID 記録の無い古い形式のリグ、および AutoRigForHumanoid 以外で作られたファイルは、インポートのみ行い UUID 復元はスキップします(警告を出します)。

### ブレンドシェイプコントローラー(`blendshape.py`)

スキンクラスター付きメッシュのブレンドシェイプを操作する、枠内を動かして値を変えるコントローラー(`Con_BlendShape_<名前>` と枠 `Frame_BlendShape_<名前>`)を作ります。

1. `オブジェクト` にメッシュのトランスフォームを割り当て、`シェイプ` / `スキンクラスター` / `ブレンドシェイプ` を自動割り当てします。
2. `適用` を押すと、ブレンドシェイプのターゲット名が各コントローラーの選択メニューに入ります。
3. 種類を選び、名前・カラー・対応するブレンドシェイプを指定して `作成` を押します。

| 種類 | 内容 |
|---|---|
| 1*1 | 1 軸・1 ターゲット |
| 2*1 | 1 軸・プラス/マイナスの 2 ターゲット |
| 1*2 | 2 軸・各 1 ターゲット |
| 2*2 | 2 軸・各軸プラス/マイナスの 4 ターゲット |

### FBX(アクセサリ > FBX タブ)

**FBXインポート** (`fbx_shape_rename.py`)
- `Import FBX`: FBX ファイルをシーンへインポートします。
- `Freeze Scale`: 選択したジョイント階層のスケールを平行移動へ焼き込んでスケールを 1 に戻し、スキンクラスターの `bindPreMatrix` を現在の状態へ同期します。
  スケール付きで取り込まれた FBX の見た目が崩れる場合に使います。

**Unity FBX 書き出し** (`unity_fbx_export.py`)
元のシーンを保護したまま、検証付きでアニメーション付き FBX を書き出します。使い方と精度は [UNITY_FBX_EXPORT.md](UNITY_FBX_EXPORT.md) を参照してください。
Unity 側のインポート設定を補助するエディタースクリプトは [`unity/Editor/AutoRigFbxImport.cs`](unity/Editor/AutoRigFbxImport.cs) です。

**FBX名の整形** (`fbx_shape_rename.py`, `blendshape_name.json`)
ASCII FBX 内のブレンドシェイプ名を一括で置換した別 FBX を作ります(日本語名などを Unity 向けの名前に変換/復元)。
現在のシーンには触れず、ファイルからファイルへ変換します。

1. `変換元 FBX` を指定します(Json と変換後 FBX のパスが自動入力されます)。
2. `Json出力` で、元の名前→変換後の名前の対応表を作ります。変換後の名前が重複するとエラーにします。
   既定の変換表は [`blendshape_name.json`](blendshape_name.json) です。
3. Json の変換後の名前を必要に応じて編集します。
4. モード(`Kay To Value`: 元→変換後 / `Value To Kay`: 変換後→元)を選んで `FBX出力` を押します。

## 作られるリグの仕様

- **構成**: `<キャラクター名>_Rig` の下に `Grp_C_<キャラクター名>Rig` があり、コントローラー(`Con_*`)がぶら下がります。Root は Root1〜Root3 の複数階層です。
- **体幹**: SpineIK / ChestIK / ChestFK / UpperChest など。SpineIK と ChestIK には `stretch` アトリビュートがあります。
- **頭**: Neck / Head / 左右の Eye と、目線を制御する EyeAim(中央・左右)。
- **腕・脚**: FK と IK を持ち、`Con_*_Shoulder`(腕)/ `Con_*_LegRoot`(脚)の `IKFK` アトリビュート(0〜1。0=IK、1=FK、間はブレンド)で切り替えます。作成直後の値は腕が FK(1)、脚が IK(0)です。
  - IK は Pole Vector(ArmPV / LegPV)付きで、IK ハンドル側に `stretch` と、上腕・前腕(大腿・下腿)ごとの伸縮倍率を持ちます。
  - 一直線のポーズ(T ポーズなど)でも、脚は正面側(+Z)、腕は背面側(−Z)へ曲がるように初期姿勢が決められます。
  - 足は FootFK / ToesFK / ToesIK などのコントローラーを持ちます。
- **手・指**: Wrist、指ごとの FK コントローラー(Metacarpal を含む場合は対応)、指をまとめて操作する FingerBundle。
  指のジョイントが無いモデルでは作られません。
- **Setting**: `Con_C_Setting` の表示切り替えアトリビュートで、腕・脚・手・頭・体幹などの表示を切り替えます(Picker の *Vis ボタンと連動)。
- **Undo**: リグ作成全体が 1 回の Undo で戻ります。

## テスト

`tests/maya_regression.py` は `mayapy` で実行する回帰テストです。使い捨てのシーンを出力するフォルダを引数に渡します。

```bash
"C:/Program Files/Autodesk/Maya2025/bin/mayapy.exe" tests/maya_regression.py <出力フォルダ>
```

出力フォルダの既存ファイルは上書きせず、エラーにします。GUI の見た目・ボタン操作は mayapy(standalone)では検証できないため、対話式の Maya で確認してください。

## 制限事項

- 二足歩行のヒューマノイド向けです。四足・多脚などは想定していません。
- 一直線に近い手足のポーズは、初期姿勢へ微小な曲げを入れて IK の曲がる側を決めています。腕・脚が最初から明確に曲がっているモデルでは、その曲がりをそのまま使います。
- Picker と別ファイル読み込みは、UUID の記録があるリグ(このツールで作った、比較的新しい形式のリグ)を前提にします。
- Unity FBX 書き出しの検証は 9 フレームのサンプルで行い、全フレーム・全頂点の検証ではありません。詳細は [UNITY_FBX_EXPORT.md](UNITY_FBX_EXPORT.md) を参照してください。
- このリポジトリは公開されています。作業中のシーンやアセット(`.ma` / `.mb` / `.fbx`)は `.gitignore` で除外されているため、コミットしないでください。
